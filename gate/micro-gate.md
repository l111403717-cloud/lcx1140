## Harness 门禁（Micro-Gate）
1. 纯问答/只读分析不判级。要改代码时先输出一行：`[HX T0|T1|T2 · 理由]`。
2. T0 = ≤2 个文件、无依赖/配置/接口变更、单会话完成 → 直接改，改后跑 `hx verify --quick`。
3. 命中任一条即 T1/T2，先加载 skill `harness-architect` 再动手：≥3 文件或跨模块；改依赖/配置/数据库/鉴权/部署；需跨会话接力；用户说“重构/大改”。
4. T0 执行中实际触及 >2 文件，或验证连环报错 → 立即停下，升级 T1，不得继续以 T0 名义推进。
5. 红线：不删/改/注释/skip 既有测试与断言；不改验证命令、lint、tsconfig 规则来“变绿”；不用吞异常、硬编码返回值、`|| true` 冒充通过。
6. 临时脚本、日志、状态只写 `.harness/` 或系统临时目录，禁止落在项目根目录。
7. 不回滚、不覆盖用户已有的未提交改动；要改到这些文件时先告知。
8. 宣称“完成/通过”必须附上实际命令和退出码；没跑就写 NOT_RUN，不得推测为通过。
9. `hx` 不可用或项目没有工具链时，按降级链自查：typecheck → lint → build → 冒烟运行 → diff 范围审计，并逐项注明结果。
