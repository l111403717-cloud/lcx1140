# 实施与验证细则

普通开发需要核对边界、选择验证工具或处理失败与等待时读取；已知可用的规则和证据直接复用。

### 1.1 边界保护（仅在相关情形启用）
- 常规任务核对实际 diff 与真实验证；仅高风险或用户明确要求固定验收契约时，对选定验证文件计算 SHA256，不默认锁整个工具链。
1. **按实际风险升档**：文件数、跨目录或一次测试失败只触发重新判级，不自动创建持久文件或升到 Tier 2。只有发现不可逆副作用、关键接口风险、真实交接需要或范围明显失控时才提高控制强度；保留已有成果，不重跑全部准备步骤。
2. **允许正常维护测试**：在授权范围内可新增或修正测试、构建入口及依赖声明；修改现有断言须对应真实需求变化并审查理由，不能为了变绿而削弱覆盖。可疑删除、跳过或仅运行单例须核查，不把所有合理测试修改一律判为作弊。已明确锁定的验收契约须先说明变更并获得授权。
3. **按需保护重叠修改**：将覆盖已有未提交内容且难以精确恢复时，才备份受影响文件到 `.harness/snapshots/`；普通可审查的局部补丁无需批量备份。失败不自动恢复整个快照；仅撤销本次确认的改动，避免抹掉期间其他人的编辑。
4. **地图锚点保鲜校验（Map Freshness Check）**：使用项目所在平台的原生方式确认地图中涉及的目标路径存在。若发现路径漂移或地图过期，仅针对当前关联子目录定位并修正；仅在本任务已使用 PLAN 时记录，不因此创建全套文档。

## 3. 原生工具链自适应契约（Native Toolchain Adapter）
按项目根目录特征文件自动映射原生探针与验证器，严禁强绑 Python：
1. Node/TS (`package.json`)：`node -v` + `npm/pnpm/yarn/bun run <typecheck|lint|test|build>`
2. Rust (`Cargo.toml`)：`cargo --version` + `cargo check` / `cargo test`
3. Go (`go.mod`)：`go version` + `go vet ./...` / `go test ./...`
4. Python (`pyproject.toml`/`requirements.txt`)：`python3 --version` + `pytest` / `ruff` / `pyright`
5. 通用构建 (`Makefile`/`Justfile`/`Taskfile.yml`)：优先调用已定义的 `check` / `test` / `verify`
6. 复用已知可用环境，不为每阶段重复查版本。无现成验证器时选择最小有意义的检查，并如实标明覆盖；确需控制脚本时才放入 `.harness/`，不为了满足门禁制造没有验证价值的探针。

### 4.1 执行、返工与等待预算
- 信息足够时直接开始，不设置固定的“准备时长”或等待仪式；只有存在具体未知点时才继续定点调查，并在没有新证据时停止重复准备。
- 首轮实现后先跑定向验证；共享接口/依赖受影响或最终交付时按需跑回归/构建。源码、环境、验证契约未变时复用同一份证据，不反复执行相同检查。
- 同一失败链默认只做 1 次针对性修复，包含主代理修复、子代理返工和应用内模型调用修正；若出现新证据、明确的新修复路径且预计收益高于再调用一次模型的成本，可再尝试 1 次。不重复同一方案，也不按层叠加次数。
- 外部模型/网络相同错误最多主动重试 1 次，不叠加已有 SDK/宿主重试；先核对已有调用是否仍在运行，避免重复请求。失败后隔离不可用环节，继续可独立完成的本地工作，真实调用未成功就标未验证。
- 不要为了委派而主动制造失败、重复跑探针或嵌套启动整套 CLI；只有用户明确要求回归/故障演练时才这样做。
- 优先使用已有等待/异步完成机制，避免 `sleep + ps + 读输出` 高频轮询。不要为委派或验收随意嵌套启动整套 CLI；只有目标产品确实依赖该集成链路且已授权时才测试，并优先用本地 fixture 隔离验证。
- 上下文长时仅保留目标、当前改动、验证证据和下一步，不把全部历史重复塞入每次调用。压缩次数不触发重新规划，也不声称自动切换了新对话；需要真实交接时写精简接力点，遵守宿主能力和用户授权。
