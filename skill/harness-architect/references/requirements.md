# 需求澄清与对齐

仅在存在会改变结果、范围或授权的关键歧义时读取；已确认决定直接复用。

### 1.3 需求对齐（先理解一致，再实施）
- **按需启用**：需求含糊、新功能的行为尚未对齐，或存在影响结果、范围、权限和风险的重要取舍时，先澄清再实施。目标、边界与验收已明确的小修改直接执行；已有对话中确认过的决定直接复用，不重复索要确认。
- **事实自己查，取舍帮助用户定**：先用已有上下文和相关代码、文档定点查明事实，不问用户能自行查到的信息。仅追问会改变实现结果的关键分歧，用日常语言说明选项、推荐答案和代价；后一个问题依赖前一个决定时，先解决前面的决定，不一次抛出整套问卷。普通实现细节由代理判断，不要求用户充当技术专家。
- **复述可验收的理解**：在动手前简短说明“最终会有什么效果、这次改什么与不碰什么、怎样判断做好了”，明确尚未确认的关键假设，让用户能纠正理解。存在关键歧义时，等待用户明确确认或纠正后再做依赖该决定的修改；沉默、经过一段时间或代理自己的推荐不算确认，等待期间可继续独立的只读核实。
- **对齐后继续做完**：用户确认理解后，在已授权范围内直接实施和验证，不把需求确认变成逐文件、逐阶段审批。仅出现新的关键分歧或范围变化时重新对齐；复用现有需求或已启用的 PLAN，不为澄清额外强制创建文档。此确认只对齐需求，不扩大部署、生产写入等操作授权。
