# Codex 宿主适配契约（子代理与多模型协作）

本文档仅在 Codex 环境中使用。Antigravity（反重力）环境无需读取本文件。

## 1. Codex 原生子代理（spawn_agent）适配

Codex 的原生 `spawn_agent` / 子代理能力可以用于 AUTO 模式，但这里的隔离是**会话级和任务范围级隔离**，不是文件权限隔离。启用条件如下：

1. **角色分工**：单模型时当前主代理直接实施与验收；采用 GPT -> DeepSeek 协作时，GPT 是唯一的 Harness 调度器和状态写入者，DeepSeek 执行子代理不得修改 Harness/全局状态、计划或配置。不把所有主模型为 DeepSeek 的对话误当成执行子代理。
2. **单一任务包**：每个子代理必须只接收一个任务包，并且有明确的 `scope.include`、`scope.exclude` 和验收命令。
3. **写入范围无重叠**：并行子代理的写入范围不得重叠；共享接口、配置文件、数据库、部署文件和生产文件不得自动并行修改。
4. **高危操作主控拦截**：DeepSeek 只能执行低风险、可复核的实现、搜索和测试任务；密钥、权限、Codex/CC Switch 配置、生产、支付、删除和迁移任务必须由 GPT 主控。
5. **真实证据验收**：主代理检查子代理的真实 diff、退出码和验收证据；不能只采信完成报告。返工使用统一预算，不另叠加子代理重试次数；只传必要上下文和失败证据。
6. **物理隔离回退**：需要物理文件隔离、涉及高风险写入或无法保证单写入者时，改用独立 worktree 或 MANUAL 模式，不使用 Codex 原生 AUTO。

> [!NOTE]
> Codex 的 AUTO 模式定义为：`PROCEDURAL_AUTO`（流程级自动），不是 `PHYSICAL_ISOLATION_AUTO`（物理隔离自动）。不得把子代理提示词、skill 或任务包描述成安全边界。

## 2. 只读验收裁判代理（harness-verifier）

在 Tier 1 / Tier 2 收尾验收阶段，主代理可派发 `harness-verifier` 独立运行验收命令：
- 裁判只运行 `hx verify` / `git diff` 并如实记录退出码与输出。
- 裁判禁止编辑任何业务文件，不为了通过测试而擅改命令。
