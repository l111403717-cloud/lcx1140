# 通用开发防护栏与质检清单 (QA & Guardrails Checklist)

任何大模型在进入工程实施时，必须受到以下三大维度的“物理级硬约束”：

---

## 一、物理与环境防护栏 (Physical Guardrails)
1. **内存与资源硬指标**：
   - 检查当前宿主机可用内存（例如低于 2.5GB 必须强行终止构建）；
   - 设置单个进程最长超时时间（例如 Gradle 构建超 180 秒自动 `kill` 进程，防止死锁卡死）。
2. **环境路径死锁**：
   - 强制指定唯一的解释器或运行时路径（如固定 `D:\安卓\jbr` 的 JDK 21，禁止使用全局默认环境变量）。

---

## 二、受限执行工具白名单 (Bounded Tool Execution)
1. **剥夺裸终端权限**：
   - 严禁让大模型直接拥有自由执行任意 shell 的权限；
   - 所有动作必须收敛为确定性的 Python / 批处理脚本（如 `check_syntax.py`、`locate.py`）。
2. **参数白名单校验**：
   - 脚本内部严格过滤路径与参数，杜绝越界访问或破坏性覆盖。

---

## 三、事后验货断言规范 (Verification Assertions)
1. **不听模型说辞，只看退出状态码**：
   - 必须通过 `exitCode == 0` 以及编译器 0 Error 判定；
2. **前后状态对比 (State Assertion)**：
   - 数据库变动前后对比记录行数；
   - 静态检查无告警增加；
3. **熔断与快照策略 (Error Snapshot)**：
   - 连续失败最多重试 2~3 次；
   - 触发上限后，严禁静默回滚，必须保存当前失败的改动快照（如 Git 临时分支或 patch 文件），留给人类审查。
