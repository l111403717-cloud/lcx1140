# 完整范围验收

完整 PRD 或目标模式任务开工时读取目标登记与范围清单，阶段验收和收尾时核对证据与完成门槛。普通小任务使用入口中的完成要求即可。

### 4.2 完整范围验收与完成判定
- **目标登记**：用户明确要求目标模式时，实际登记交付结果、已确认的 PRD／后续修订来源及完成条件，并核对保存的目标；不能只登记“读取附件”“继续执行”。完整细节引用原文件，不重复抄写；普通任务不强制开启目标模式。
- **范围清单**：实施完整 PRD 时，将本轮全部应交付项对应到精简验收清单，包括不适合自动测试的内容要求。记录需求来源、实现位置／交付物、验证证据及状态（待实现、待验证、已通过、局部阻塞）；优先复用现有 PLAN，未启用持久 Harness 时在当前任务上下文核对，不额外建台账。用户已明确排除或允许后续处理的事项注明依据，不算本轮缺口；不得自行删项或降级需求。
- **证据覆盖**：代码已写、构建成功、页面可打开、发布成功或抽样通过，只证明对应部分，不能替代逐项验收。按需求性质检查实际行为、内容或集成；占位、模拟及未接通流程不得冒充真实完成，除非需求明确允许。
- **停止前核对**：每次准备结束执行或标记目标完成前，检查全部应交付项及剩余可执行工作。仍有已授权且可独立推进的事项时继续实施、验证和收尾，不逐阶段等待批准；遵守用户明确停止要求及宿主运行限制。
- **局部阻塞**：缺资料、权限或外部依赖只阻塞相关事项，继续其他可做工作。剩余工作确实均无法推进或受到运行限制时，报告原因、证据、未完成项和恢复步骤，按需保留接力；状态操作遵循宿主工具契约，不自行改变阻塞阈值、预算或重试规则。
- **完成门槛**：只有全部本轮应交付项达到约定验收标准，才能宣称完整完成或标记 `complete`／`DELIVERED`。存在未交付或关键未验证项时如实报告部分进展；不得把局部受阻、预算耗尽或运行中断标为完成，也不得通过缩小范围、降低标准或将难项改成后续建议来凑齐完成。
- **验收适量**：检查强度与实际风险相称，复用仍有效的证据，不增加无关审批、工具或重复验证。区分外部检查完成与不可控的外部结果达成；结果属于约定交付条件而未达成时如实列为未完成，不编造资料、猜测业务事实或无限轮询。

## 6. 汇报规范（简洁、以交付为中心）
- 开始时一句话说明目标与必要边界，随后执行；不要逐工具播报状态机。
- 有实际进展、长等待、范围变化或真实阻塞时才更新：做成了什么、卡在哪里、接下来做什么。只有需要用户决策时才提问，不在每阶段等确认。
- 最终简报：按上述验收规则报告完成范围、实际验证结果、未完成/未验证项；部分进展与完整交付明确区分，没有对应验收证据不能写 PASS/DELIVERED。
- Tier 1/2 只在阶段完成、失败、交接时更新状态与简短证据；不强制输出大面板或每次工具调用落状态。
